# Sprint 1 assessment

Answer each question **in your own words**, with an example from your own team or project where you can. Short and honest beats long and copied.

## 1. How long is each sprint in this programme?

Each sprint lasts for two weeks. During this period, the team plans and completes a small set of tasks.

## 2. Which role rotates every sprint?

The Scrum Master role rotates every sprint so that different team members can take responsibility for managing the team's process.

## 3. What is the purpose of a retrospective?

A retrospective helps the team discuss what went well, what problems they faced, and what they can improve in the next sprint.

## 4. Where should your day-to-day code changes go?

Code changes should go into a separate working branch instead of directly into the main branch. After completing the work, we should create a pull request for review.

## 5. You accidentally committed an API key. What is the right response?

I should treat the API key as leaked, replace or revoke it immediately, and make sure the new key is not committed to the repository.

## 6. When should you tell the team you are blocked?

I should inform the team on the same day when I face a blocker instead of waiting until the end of the sprint.

## Reflection

What was hardest this sprint, and what will you do differently next time?

The hardest part of this sprint was understanding Git branches, commits, and error handling while working with the GitHub API. I practised different repository names and learned how to handle invalid repository errors. Next time, I will plan my tasks clearly, practise Git commands regularly, and communicate blockers early.
