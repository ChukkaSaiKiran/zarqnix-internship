## 1. Sprints
- A sprint is a fixed two-week period.
- The team plans and completes a small set of tasks.

## 2. Five Team Roles
- Product Owner: Decides what to build.
- Scrum Master: Maintains the team's process and removes blockers.
- Lead Developer: Guides technical decisions.
- Designer: Designs the product look and feel.
- QA and Docs: Tests the product and prepares documentation.

## 3. Sprint Ceremonies
- Planning: Select sprint tasks.
- Daily Check-in: Share progress and blockers.
- Review: Demonstrate completed work.
- Retrospective: Identify improvements.

## 4. Git Basics
- Git tracks project changes.
- Commit saves a snapshot.
- Branch provides a separate line of work.
- Push uploads changes to GitHub.
- Pull Request requests code review and merging.

## 5. Git Commands
```bash
git switch -c sprint-1
git add .
git commit -m "Complete Sprint 1 work"
git push -u origin sprint-1
```

## 6. Git Best Practices
- Never commit directly to main.
- Commit small changes regularly.
- Pull the latest main before opening a PR.
- Never commit passwords, tokens or API keys.

## 7. Remote Team Communication
- Share complete updates.
- Report blockers on the same day.
- Record decisions on the sprint board or team chat.
- Assume good intent and communicate clearly.
